# MChemistry：化学平衡与勒夏特列原理实施方案

## 建议的目标

玩家改变浓度、温度、气体空间或移走产物后，体系逐渐达到新的平衡；颜色、沉淀量、气体颜色和压力随真实组成变化。勒夏特列原理作为这些计算结果的解释，不单独写成“加热就向右”等固定规则。

本文件是方案，本次不启用新的通用平衡引擎。

## 现有基础和缺口

已有 SolutionSpecies/SpeciesInventory 离子与配合物视图、Fe³⁺/SCN⁻ 平衡计算、温度溶解度曲线、真实质量容器和气路。当前铁—硫氰酸根是固定常数113 L/mol的平衡快照，并非所有物种的可写库存；ReactionEngine仍以单向配方推进，气路边界仍为整数mL。

需要补齐：统一的可写物种账本、平衡反应数据、温度相关常数、气液分配、平衡与旧配方互斥，以及相变/传热的能量协调。不能把显示用的离子快照再叠加成另一份物质。

## 推荐的三阶段

### 第一阶段：铁—硫氰酸根的浓度与温度平衡

沿用 Fe³⁺ + SCN⁻ ⇌ FeSCN²⁺，升级已有体系。加入任一反应物、稀释、取出一部分溶液后重新求解；加热/冷却的变化由带出处的K(T)决定，缺少可靠热力学数据时只启用浓度版本，不编造定量变色幅度。

颜色读取实际自由离子与配合物浓度。先按有界求根算出目标组成，再以速率限制逐步接近；速率作为游戏参数单列，避免把动画速度伪装成实测动力学。

护目镜普通界面显示“向生成配合物方向变化／向解离方向变化／已接近平衡”，按住潜行才显示Q、K和各物种浓度。达到动态平衡时宏观净变化停止，正逆反应并未消失。

### 第二阶段：沉淀平衡，与过滤联动

选一个有可靠数据的难溶盐（优先草酸钙，其次AgCl）实现Ksp；加入同离子改变溶解量，加水或改变配合条件可能使沉淀重新溶解。溶解度曲线与Ksp不能同时独立消耗同一份固体；对已接入Ksp的物质由统一平衡调度接管。

过滤真正移走固体相或溶液相。**只取走一部分纯固体，只要固相仍存在且温度不变，不会仅因固体数量减少而改变饱和溶液的平衡浓度。** 移走溶液、消耗溶解离子或改变温度才按新条件计算；固相完全耗尽时重新判定未饱和状态。

### 第三阶段：气体平衡与压力

推荐 2NO₂(g) ⇌ N₂O₄(g)，棕色与浅色变化便于观察温度、压缩及泄压影响。增加密闭气体池，以mol保存，按气相自由体积和T计算各分压；现有整数mL管道仅作输送边界，小数留在源端。

压力操作应通过活塞/可变容积容器或真实压缩设备实现。普通刚性玻璃瓶不能凭点击任意缩容。温度改变K；改变体积改变分压与Q。加入惰性气体时区分恒容与恒压：恒容、恒温时反应气体分压不变，不能按总压上升误判平衡移动。

## 计算规则

- 每条平衡记录计量系数、相态、K在参考温度下的数值、标准态与数据来源。稀溶液第一版采用理想活度近似，界面明确适用范围。
- 反应商Q与K使用一致的量纲/标准态；纯固体和纯液体通常按活度1处理，物种不存在时另外执行相稳定性和限量判定，不能直接把零带入对数。
- Q<K趋向正反应，Q>K趋向逆反应；在log(Q/K)容差内停止净推进，避免末尾抖动。
- 有可靠反应焓时，用范特霍夫关系在有限温区近似K(T)，温度使用K。热效应按实际反应进度乘反应焓结算，使用体系热容；与已有相变潜热共用能量入口。
- 催化剂加快达到平衡的过程，**不改变K或最终平衡组成**；搅拌优先影响传质速度。
- 多条平衡共享物种时联合迭代/耦合求解，不按配方表顺序把原料先耗光。

## 存储与旧系统迁移

建议新增带版本号的 ChemicalState，按相态保存物种mol、温度/能量状态、气相体积。以该账本作为唯一真实库存；旧LabVesselItem条目通过适配器供UI、倒液、过滤、蒸馏、电解读取和原子提交。

迁移时由明确化学式和既有质量换算，保留旧存档原数据备份；未知条目原样保留。不能从溶液ID再次补入默认水，也不能同时把中性盐与由它展开的离子算两份。所有操作采用试算、校验非负/容量/元素和电荷、一次性提交。

迁移按白名单逐体系推进：被平衡接管的反应从旧单向反应引擎排除；未接管的配方继续原逻辑。读取不改变物质量，颜色计算不写回库存。

## 验收

1. 从不同初始配比接近同一个平衡状态；物质量非负、元素与电荷守恒。
2. 加反应物、稀释、升降温后方向正确，可逆操作能恢复相应平衡。
3. 催化剂改变用时但不改变终态；没有催化剂也不会凭空禁用热力学允许的平衡。
4. 沉淀生成/溶解、过滤移除与湿滤渣保液共同守恒；部分移走纯固体不错误改变饱和浓度。
5. 气体压缩、恒容加惰性气体、开口逸散分开测试。
6. 反复保存加载、分装混合、电解/蒸馏同时运行不复制物质或热量。

## 实施建议

先完成第一阶段及统一转移接口，再推进Ksp与过滤联动，最后引入压力设备和气体平衡。第一阶段主要是程序和界面工作，无需新模型；第三阶段可制作可变容积气体容器、活塞与压力表。
